# Change Request

## Мета

Change Request (CR) використовується для формального опису запропонованої зміни до погодженого Scope, Requirements або Business Process.

Документ дозволяє зафіксувати причину зміни, її очікуваний результат, вплив на процеси та пов'язані артефакти.

---

# CR-001 — Автоматизація резервування продукції

## Статус

**Proposed**

## Ініціатор

Менеджер з продажу

## Дата

—

## Опис зміни

Запровадити автоматизований процес резервування продукції після підтвердження отримання оплати за замовлення.

Після підтвердження оплати система повинна дозволяти встановити статус резервування та передавати інформацію відповідальним учасникам процесу.

## Business Reason

У поточному процесі резервування залежить від ручної передачі інформації між Sales, Finance та Warehouse.

Це створює ризик:

- затримки резервування;
- подвійного резервування;
- помилкового відвантаження;
- втрати актуальної інформації про доступну продукцію.

## Очікуваний результат

Після підтвердження оплати:

1. Замовлення отримує відповідний статус.
2. Продукція резервується.
3. Warehouse отримує інформацію про необхідність підготовки продукції.
4. Logistics отримує необхідну інформацію для планування відвантаження.

---

# Scope

### In Scope

- перевірка статусу оплати;
- зміна статусу замовлення;
- резервування продукції;
- передача інформації Warehouse;
- передача інформації Logistics.

### Out of Scope

- автоматичне формування виробничого плану;
- зміна алгоритму виробництва;
- автоматичний вибір перевізника;
- зміна бухгалтерського обліку.

# Impact Assessment

## Business Process

Зміна впливає на процес:

**Продаж → Оплата → Резервування → Підготовка до відвантаження → Відвантаження**

## Roles

- Accountant
- Warehouse Manager
- Logistics Manager

## System

## Data

- Reservation Status

## Impact Level

# Dependencies

- Актуальні дані про залишки продукції.
- Доступний статус оплати.
- Налаштований процес замовлення в ERP.
- Визначені права доступу користувачів.

---

# Risks

| Ризик | Вплив | Mitigation |
|---|---|---|
| Несвоєчасне оновлення статусу оплати | Затримка резервування | Визначити джерело та правило оновлення статусу |
| Некоректний залишок | Помилкове резервування | Контроль актуальності складських даних |
| Помилка користувача | Некоректний статус замовлення | Validation Rules |
| Відсутність продукції | Неможливість виконати замовлення | Перевірка доступної кількості перед резервуванням |

---

# Acceptance Criteria

- [ ] Замовлення не може бути зарезервоване без підтвердження оплати.
- [ ] Після підтвердження оплати доступна операція резервування.
- [ ] Зарезервована кількість не може перевищувати доступний залишок.
- [ ] Warehouse отримує інформацію про резервування.
- [ ] Logistics отримує необхідну інформацію для підготовки відвантаження.
- [ ] Статус замовлення відображає актуальний стан процесу.
