# 20. Definition of Done (DoD)

## Мета документа

Definition of Done (DoD) визначає єдиний для всієї Scrum-команди стандарт якості та технічної завершеності, якому повинен відповідати кожен елемент беклогу (PBI) та потенційно готовий до випуску інкремент продукту (Odoo ERP Release Candidate).

# Чек-лист Definition of Done (DoD)

PBI вважається **Done** (завершеним), якщо повністю виконано такі 8 вимог:

| № | Рівень перевірки | Критерій Done | Метод перевірки / Інструмент |
| --- | --- | --- | --- |
| **1** | **Функціональність** | Усі Acceptance Criteria (AC), описані в картці PBI, пройшли перевірку та виконані без відхилень. | QA / Manual Test |
| **2** | **Якість коду** | Код розроблено відповідно до стандарту Odoo Coding Guidelines. Проведено Code Review (мінімум 1 Senior Developer). | Git Pull Request / Review |
| **3** | **Тестування** | Написано та успішно виконано автоматичні юніт-тести Odoo (`pytest` / Odoo Test Framework). Покриття коду ≥ 80%. | CI/CD Pipeline |
| **4** | **Інтеграція** | Зміни розгорнуто на тестовому середовищі (Staging Environment) без регресій і критичних багів. | Staging Deployment |
| **5** | **Нефункціональні вимоги** | Проведено перевірку продуктивності (NFR-001), безпеки доступу (NFR-003) та збереження аудиту (NFR-004). | Security & Load Check |
| **6** | **Документація** | Оновлено технічну документацію Odoo модулів, інструкцію користувача та опис конфігурації. | Confluence / User Guide |
| **7** | **Демонстрація** | Функціонал продемонстровано Product Owner та ключовим стейкхолдерам на Sprint Review. | Sprint Demo Meeting |
| **8** | **UAT / Погодження** | Ключовий користувач (Key User / SME) підписав протокол прийняття за результатами UAT сценарію. | Signed UAT Test Case |

---

# Наслідки невиконання DoD

Якщо хоча б один пункт DoD не виконано до завершення Спринту, PBI **не вважається Done**, не включається до Інкременту Релізу і повертається до Product Backlog для переоцінки.
